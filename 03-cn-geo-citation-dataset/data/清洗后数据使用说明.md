## 数据之间如何连接

`citation_observations` 是全库的中心表。每条引用通过 `question_id` 连接问题，通过 `platform_code` 连接 AI 平台，通过 `source_id` 连接信源，通过 `page_id` 连接页面。当前原始数据缺少可靠的单次回答边界，`response_id` 保持为空，`responses.parquet` 只保留未来数据所需的正式表结构。

问题标签采用多标签结构。当前每个问题只继承一个旧目录标签，因此 620 个问题对应 620 条标签。后续可以给同一个 `question_id` 增加行业、意图、时间敏感度、场景和提示风格等多个标签，无需改动问题主表。

## 从哪些表开始用

日常分析可以从 `marts/` 开始：来源排行榜用 `source_visibility`，平台共识用 `platform_overlap`，高覆盖页面和标题研究用 `content_performance` 连接 `page_features`。需要切到某个行业或问题时，再连接 `questions` 和 `question_labels`。需要核对原始链接、摘要或清洗状态时，回到 `citation_observations`。

字段可用性按分析任务解释。发布时间未知的记录仍可参与平台、问题、信源和引用观察统计；标题或摘要未提供的页面不进入对应的特征占比和长度比较；页面时间分析只使用 `published_date_status = 'consistent'` 的记录。日期冲突页面保留在其他适用分析中，并通过状态字段进入复核队列。

DuckDB 查询目录已固化常用维表和分析集市，复制数据库文件后仍可直接查询：

```python
import duckdb

con = duckdb.connect("data/catalog/cn_geo.duckdb", read_only=True)
top_sources = con.sql("""
    SELECT domain,
           sum(deduplicated_citation_count) AS citations,
           count(DISTINCT platform_code) AS platforms
    FROM source_visibility
    GROUP BY domain
    ORDER BY citations DESC
    LIMIT 20
""").fetchall()
```

全量 `citation_observations` 保留为分区 Parquet，查询时可按需创建临时视图：

```python
con.execute("""
    CREATE TEMP VIEW citation_observations AS
    SELECT *
    FROM read_parquet(
        'data/curated/citation_observations/**/*.parquet',
        hive_partitioning = true
    )
""")
```

## 清洗规则和边界

- 原始值保留在带 `_raw` 的字段中，标准值写入新字段。
- 空字符串统一为空值。日期中的 `0` 单独标为零占位符。
