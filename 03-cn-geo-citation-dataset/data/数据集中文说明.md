# CN-GEO Citation Dataset 中文说明

清洗后的 Parquet 表、中文字段对照、目录用途和查询入口见 [清洗后数据使用说明](清洗后数据使用说明.md)。本文件重点说明原始 JSONL 数据。

- 更新日期：2026-07-19
- 数据版本：2.0.1
- 数据发布日期：2026-07-14

## 这批数据记录了什么

这是一份国内生成式 AI 引用来源数据集。每一行代表某个 AI 平台回答一个问题时出现的一条外部引用，内容包括问题、回答平台、引用链接、网页标题、网站名称、发布时间、引用摘要和分类标签。

这份数据适合研究以下问题：

- 不同 AI 平台经常引用哪些网站和页面。
- 同一个问题在不同平台上的引用来源有什么差异。
- 哪些来源能覆盖多个问题、行业和平台。
- 哪类标题、网页和内容结构更容易进入 AI 引用结果。
- 某个品牌或域名在哪些目标问题中已经出现，哪些位置仍有覆盖空间。

当前数据只保留引用来源和网页摘要，没有完整回答原文、回答批次、模型版本和采集时间。现阶段适合计算来源覆盖、跨平台共识和内容特征。引用概率、品牌推荐率、情感倾向和严格的引用排名需要补充回答级数据后再计算。

公开发布前已移除 25 条引用 URL 中的用户信息，并重算对应记录哈希。原始分片清单记录了处理后的字节数和 SHA-256，构建预检会拒绝任何仍携带 URL 用户信息的记录。

## 目录结构

数据使用 JSON Lines 格式，每一行都是一条完整 JSON 记录。目录结构如下：

```text
data/
├── README.md
├── manifest.json
├── statistics.json
└── records/
    └── <layer-slug>/
        └── <subcat-slug>/
            ├── part-0001.jsonl
            ├── part-0002.jsonl
            └── ...
```

文件夹由分类字段 `layer` 和 `subcat` 决定。`part-0001.jsonl`、`part-0002.jsonl` 只是同一分类下的物理分片，没有额外的业务含义。分析一个分类时，需要合并读取该文件夹内的全部 `part-*.jsonl` 文件。程序读取时应使用 `manifest.json` 发现文件路径，避免在代码里写死目录。

## 英文字段与中文含义

所有记录都有相同的 14 个字段。字段本身存在不代表字段值一定有效，部分值可能是空字符串或 `null`。

| 英文字段 | 中文名称 | 常见类型 | 含义和用法 |
| --- | --- | --- | --- |
| `record_id` | 记录 ID | 字符串 | 每一行的唯一编号，如 `cngeo-000015832`。适合定位和追溯原始记录。 |
| `prompt` | 用户问题 | 字符串 | 提交给 AI 平台的完整问题文本，如“老牌的包子铺连锁品牌排行？”。 |
| `platform_code` | AI 回答平台代码 | 字符串 | 表示回答来自哪个 AI 产品及终端，中文映射见下文。 |
| `quote_url` | 引用链接 | 字符串 | AI 回答引用的网页地址。空字符串和 `expired_url` 等值需要标为异常 URL。 |
| `quote_title` | 引用网页标题 | 字符串 | 被引用页面的标题，可用于分析标题主题、年份、榜单和内容形式。 |
| `site_name` | 信源名称 | 字符串 | 数据中记录的网站、媒体或内容账号名称。一个域名可能对应多个 `site_name`。 |
| `quote_index` | 引用序号 | 数字、字符串或空值 | 原始回答中的引用位置。不同平台格式不同，跨平台比较前需要单独清洗。 |
| `published_at` | 信源发布时间 | 字符串 | 被引用网页的发布时间。当前混有标准日期、中文日期、Unix 时间戳和空值。 |
| `domain` | 信源主域名 | 字符串 | 从引用链接提取的主域名，如 `maigoo.com`。适合做网站级覆盖分析。 |
| `snippet` | 引用内容摘要 | 字符串 | 被引用页面的正文片段或搜索摘要，可用于提取品牌、关键词和内容结构。 |
| `prompt_id` | 问题 ID | 数字或空值 | 同一个问题的内部编号，适合连接同一问题的多平台记录。未分类数据中可能为空。 |
| `layer` | 分类层 | 字符串 | 问题所属的大类，如“行业维度”“提问属性”。 |
| `subcat` | 子分类 | 字符串 | 大类下的具体分类，如“餐饮”“对比类”。 |
| `record_hash` | 记录内容哈希 | 字符串 | 用于识别内容相同的重复记录。做统计前建议按此字段完成精确去重。 |

### 一条记录的阅读顺序

可以按下面的顺序理解一条记录：

1. `prompt_id` 和 `prompt` 表示用户问了什么。
2. `platform_code` 表示哪个 AI 平台回答了问题。
3. `quote_url`、`domain`、`site_name` 和 `quote_title` 表示 AI 引用了哪个来源。
4. `quote_index` 表示引用在原始结果中的位置。
5. `published_at` 和 `snippet` 提供信源时间与内容证据。
6. `layer` 和 `subcat` 表示问题属于哪类研究场景。
7. `record_id` 和 `record_hash` 用于追溯与去重。

## 字段可用性与处理状态

引用记录的核心事实由问题、平台和引用观察构成。网页标题、摘要、发布时间、域名和引用序号属于按平台选择性提供的元数据。某个可选字段为空时，记录仍可进入不依赖该字段的分析。下表分别说明字段状态与处理方式。

| 状态 | 全库情况 | 建议处理方式 |
| --- | --- | --- |
| 精确重复 | 24,274 条额外重复记录，约 11.34% | 保留原始表，分析表按 `record_hash` 去重并记录重复次数。 |
| `published_at` 未提供或为零占位 | 83,309 条，约 38.91% | 原值与解析状态保留；记录继续参与非时间分析，时间分析标记为未知。 |
| `prompt_id` 缺失 | 4,433 条，约 2.07% | 用规范化后的 `prompt` 生成临时问题键，并保留未分类标记。 |
| `snippet` 缺失 | 7,816 条，约 3.65% | 内容特征分析时排除，覆盖率分析仍可保留。 |
| `quote_index` 缺失 | 3,545 条，约 1.66% | 设置为空值，避免补成 0。 |
| `quote_index` 类型不统一 | Kimi 使用 `web_search:1#2` 等字符串，其他平台多为数字或空值 | 按平台解析，保留原始值并增加标准化序号字段。 |
| URL 异常 | 1,738 条非空异常值，1,133 条空值 | 增加 URL 状态，清理跳转参数并生成规范 URL。 |
| 域名与发布者不一一对应 | 腾讯、百度、头条等域名承载多个账号 | 同时使用 `domain` 和 `site_name`，需要时再提取账号名称。 |
| 回答边界缺失 | 同一问题和平台下 `quote_index` 会重复出现 | 从原始数据恢复 `run_id` 或 `response_id`，恢复前不计算单次回答排名。 |
| 平台版本缺失 | 没有模型版本和采集时间 | 后续采集增加 `model_name`、`model_version` 和 `collected_at`。 |

页面层另有 43,675 个发布时间未知页面和 670 个发布时间冲突页面。冲突表示同一规范 URL 观察到多个不同日期。时间分析使用唯一一致日期，未知和冲突页面继续参与其他适用分析。

## 推荐的分析口径

### 来源覆盖率

统计某个域名覆盖了多少个不同的“问题与平台”组合：

```text
来源覆盖率 = 引用该域名的问题与平台组合数 ÷ 全部有效问题与平台组合数
```

这个指标比原始引用行数更适合当前数据，因为同一引用可能来自多次采集。

### 跨平台共识

统计同一个问题下，有多少平台引用了同一个规范 URL 或域名。平台数越多，说明该来源的跨平台覆盖越广。

### 问题覆盖广度

统计某个域名或品牌进入了多少个不同问题，适合判断内容是否只覆盖少量关键词。

### 平台覆盖广度

统计某个域名或品牌进入了多少个不同 AI 平台，适合识别单平台来源和跨平台来源。

### 行业与意图渗透

使用 `layer` 和 `subcat` 比较来源在餐饮、金融、法律、口碑类、对比类等场景中的覆盖差异。

### 内容特征

结合 `quote_title`、`snippet` 和 `published_at` 提取标题形式、内容长度、年份、榜单、测评、指南、地域、价格和权威背书等特征，再比较这些特征与来源覆盖的关系。

## 使用边界

- 原始引用条数会受到重复采集影响，统计前需要说明去重口径。
- 当前 `quote_index` 无法直接作为跨平台排名使用。
- `snippet` 是信源片段，不能代表 AI 完整回答或品牌态度。
- 数据中的网页内容可能包含广告、软文、错误信息和过期信息，引用出现不等于内容可信。
- 当前数据可以观察相关性，不能单独证明某种内容写法导致 AI 引用。
- 品牌推荐率、情感分析和竞品排名需要完整回答文本支持。

## 当前已具备的分析基础

- 全库清洗表、字段解析状态和数据质量报告已经生成。
- 信源可见度、跨平台重合度、页面表现和页面内容特征已经生成独立分析表。
- 问题、平台、信源、页面和引用观察已经拆成可连接的标准实体。
- 指定品牌的 GEO 覆盖诊断需要补充品牌名、官网域名和竞品范围后生成。
- 趋势分析需要后续按固定问题重复采集，并补充回答批次、采集时间和模型版本。
